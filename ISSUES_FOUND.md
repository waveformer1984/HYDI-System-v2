- `lib/protoforge/policy-engine.js:257`'s empty catch — see #14 above.
- `keeper/vault/versioned-vault.js` and two `cleanup/*.ps1` scripts matched
  the new secret-scanner patterns but are false positives: the vault file
  uses a literal `"sk_live_"`-prefixed placeholder string (not a real key), and the cleanup
  scripts contain a secret-*detection* regex list (a scanning tool, not an
  instance of what it scans for) — see `tests/unit/no-hardcoded-secrets.test.js`'s
  allowlist for the exact reasoning per file.
- `public/client-dashboard.html`'s hardcoded Supabase anon key — this is
  the expected, by-design pattern (anon keys are meant to be public
  client-side, protected by RLS), materially different from the
  `service_role` leaks above. Not a bug.
